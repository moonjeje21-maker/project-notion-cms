# 인테리어 소품 후보 모아보기 — 서비스 계획 (초안 v4)

작성일: 2026-10-09 · 상태: **계획 초안 (구현 전)**

v4 변경: MVP를 "목록 한 화면"으로 줄임. 상세 페이지·정렬·주소 쿼리 필터 제거. Notion 필수 입력을 이름·상품 링크 2칸으로 줄임(종류·이미지 URL은 선택). 3단계 서술과 위험 요소를 MVP에 필요한 만큼만 남김.

## 1. 프로젝트 개요

- **프로젝트명**: 인테리어 소품 후보 모아보기
- **목적**: 사고 싶은 인테리어 소품(가구·조명·화분·수납 등)을 한곳에 모아 보고 구매를 결정하기 위함. 1차는 "모아보기"에 집중하고, 가격·크기 비교는 다음 단계에서 붙인다
- **Notion을 CMS로 쓰는 이유**: Notion 표(데이터베이스)에 소품을 한 줄 추가하면 웹에 자동으로 반영된다. 입력 화면·관리자 로그인·저장용 데이터베이스 서버를 따로 만들 필요가 없다
  - CMS(Content Management System): 웹에 보여줄 내용을 넣고 고치는 도구. 여기서는 Notion이 그 역할을 한다
- **입력 원칙**: Notion에는 이름과 링크만 넣으면 끝. 나머지는 여유 있을 때 채운다. 입력이 번거로우면 모으는 습관이 끊기기 때문
- **사용자**: 나 + 지인 몇 명. 입력은 나만 Notion에서 하고, 웹은 읽기 전용
- **공개 범위**: 로그인 없음. 주소를 아는 사람은 누구나 볼 수 있다. 검색 엔진 색인도 막지 않는다 (2026-10-09 결정, 10장)

## 2. MVP 기능

화면은 **목록 하나**다.

1. Notion 데이터베이스에서 소품 전체(이름·상품 링크·종류·이미지 URL)를 가져온다. 순서는 Notion 생성 시각 역순(최근 추가가 위)
2. 카드 그리드로 이미지·이름·종류를 보여준다. 카드를 누르면 구매 링크가 새 탭으로 열린다
3. 종류 필터: 상단 칩(전체·조명·화분…)을 눌러 거른다. 브라우저 안에서만 동작하고 주소는 바뀌지 않는다
4. 자동 갱신: Notion에서 고친 내용이 몇 분 안에 웹에 반영된다 (ISR, 5장)
5. 반응형: 휴대폰 2열, 데스크톱 4열

### MVP 제외

- 상세 페이지 (보여줄 정보가 카드와 같아서 뺌. 가격·크기가 생기면 그때 만든다)
- 가격·크기 표시와 비교, 상품 링크에서 가격·이미지 자동 수집 → 1단계 사용 후 결정 (8장)
- 정렬 선택, 필터 값 주소 공유, 공간별 필터, 이름 검색, 비교 화면, 로그인, 웹에서 입력

## 3. 기술 스택

| 구분 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | **Next.js 16.3.8** (App Router), React 19, TypeScript | 이 저장소에 이미 설치됨. 캐시·설정 방식은 `node_modules/next/dist/docs/` 문서 기준 |
| CMS 연동 | Notion API, `@notionhq/client` **5.x** (현재 5.27.0) | 5 버전부터 "데이터베이스 → 데이터 소스" 단계가 생겨 조회 방법이 바뀜. 설치 전 `.claude/rules/library-docs.md`대로 공식 문서 확인 |
| 스타일 | Tailwind CSS 4, shadcn/ui (radix-nova), lucide-react | 색은 토큰 클래스만 사용 |
| 배포 | Vercel 무료 플랜 | 2단계 |
| 비밀값 | `.env.local` — `NOTION_API_KEY`, `NOTION_DATA_SOURCE_ID` | git에 올리지 않는다. SDK 5.x는 데이터베이스 ID가 아니라 **데이터 소스 ID**로 조회한다 (Notion 앱 "데이터 소스 관리 → 데이터 소스 ID 복사") |

## 4. Notion 데이터베이스 구조

새로 만든다. 4개 열이지만 **매번 채우는 칸은 2개**다. 열 이름은 코드에서 그대로 참조하므로 한 번 정하면 바꾸지 않는다.

| 열 이름 | 속성 종류 | 입력 | 비웠을 때 웹 처리 |
|---|---|---|---|
| 이름 | 제목 | **필수** | (Notion 제목은 비울 수 없음) |
| 상품 링크 | URL | **필수** | 링크 없는 카드는 눌러도 이동 안 함 |
| 종류 | 선택 | 선택 (한 번 클릭) | "기타"로 묶어서 표시 |
| 이미지 URL | URL | 선택 | 회색 대체 그림 표시 |

- 종류 시작 선택지: 가구·조명·화분·수납·러그·소품. Notion에서 추가하면 웹 필터에도 그대로 나타난다 (코드 수정 불필요)
- 이미지 URL은 쇼핑몰 사진에서 "이미지 주소 복사"로 얻는다. Notion에 직접 올린 사진은 주소가 1시간마다 바뀌어 쓰지 않는다
- 웹에서 빼고 싶은 소품은 Notion에서 행을 지우거나 보관(archive)한다. "공개" 체크박스 열은 두지 않는다
- 입력 팁 (확인 필요): Notion Web Clipper 브라우저 확장으로 상품 페이지에서 저장하면 이름과 URL이 자동으로 들어가 종류만 고르면 된다. 이 데이터베이스에 저장되도록 설정 가능한지 1단계에서 확인

## 5. 데이터 흐름

```
[Notion 데이터베이스] --Notion API--> [Next.js 서버] --캐시(ISR)--> [브라우저: 종류 필터]
       나만 입력                    몇 분마다 다시 읽음         전체 목록 받아 화면에서 거름
```

- **ISR**(Incremental Static Regeneration): 페이지를 미리 만들어 두고 정해진 시간(5분)이 지나면 다음 방문 때 뒤에서 새로 만드는 방식. 방문자는 항상 빠르고 Notion API 호출은 몇 분에 한 번
- 필터를 브라우저에서 처리하는 이유: 주소 쿼리로 서버에서 거르면 페이지가 "매번 새로 그리는 동적 페이지"가 되어 ISR 캐시가 무력화된다. 전체 목록을 한 번 캐시하고 화면에서 거르는 쪽이 단순하고 빠르다
- 이미지는 외부 URL을 일반 `<img>`로 보여준다 (`next/image`는 쇼핑몰 도메인마다 허용 목록이 필요해 MVP에서는 쓰지 않는다). 비었거나 깨지면 대체 그림

## 6. 화면

레이아웃 틀은 기존 `app/(marketing)/` (머리글 + 바닥글). `(dashboard)` 틀은 쓰지 않는다.

| 상황 | 내용 |
|---|---|
| `/` 기본 | 상단 종류 칩(전체 + 종류들) · 카드 그리드(이미지·이름·종류 배지) · 카드 클릭 시 구매 링크 새 탭 |
| 소품 0개 | "아직 소품이 없어요" 한 줄 |
| 필터 결과 0개 | "이 종류의 소품이 없어요" 한 줄 |
| Notion 연결 실패 | 기존 `app/error.tsx` ("다시 시도") |
| 이미지 없음·깨짐 | 회색 배경 + 아이콘 |

## 7. 구현 단계 (1단계 · 모아보기)

1. **Notion 준비** — 4장 구조대로 데이터베이스 생성, 샘플 소품 5~10개(이미지·종류가 빈 것도 섞어서), 통합(Integration) 생성·연결, API 키와 데이터베이스 ID 확보
   - 확인: 데이터베이스 "연결" 메뉴에 통합이 보인다
2. **연동 코드** — `@notionhq/client` 설치, `.env.local`, `src/lib/notion.ts`에 `Item` 타입(id·name·url·imageUrl·category)과 "전체 가져오기" 함수 하나. Notion 응답을 화면용 객체로 바꾸는 변환 포함. 열 이름은 이 파일에만 적는다
   - 확인: 임시로 목록을 글자로 찍어 본다
3. **목록 화면** — `app/(marketing)/page.tsx`를 소품 목록으로 교체. 카드·필터 컴포넌트는 `components/features/items/`에. 필터는 `"use client"` 컴포넌트 안의 상태 하나
   - 확인: 칩을 누르면 걸러지고, 휴대폰 폭에서 2열
4. **마무리 설정** — 빈 상태 2문구, 대체 이미지, ISR 5분, `lib/site.ts`의 사이트 이름·메뉴
   - 확인: Notion에서 이름을 고친 뒤 5분 후 반영
5. **검증** — `npm run lint`, `npm run build`, 브라우저(Playwright MCP) 스크린샷, `README.md` 화면 목록·폴더 그림 갱신
   - 확인: lint·build 오류 0

## 8. 이후 단계 (한 줄씩만)

- **2단계 · 배포**: Vercel 연결, 환경변수 등록, 지인에게 주소 공유
- **3단계 · 가격·크기**: 1단계를 써 본 뒤 "Notion에 숫자 열 추가해 직접 입력" vs "서버가 상품 링크에서 자동 수집" 중 선택. 자동 수집을 택하면 이미지 URL 입력도 없앨 수 있다. 상세 페이지는 이때 만든다
